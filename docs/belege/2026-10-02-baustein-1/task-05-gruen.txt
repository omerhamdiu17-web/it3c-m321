== Teil B: P10 und P11 von Hand nachgemessen, mit dem gebauten Jar
Die Tests prüfen nur, dass nichts Gefälschtes ankommt und dass ein 5xx innert 5 s kommt. Was genau
ankommt und welcher Status, zeigt ein Lauf des Jars (mvn -q -pl web-gateway -am package -DskipTests)
auf Port 18090. Als Keycloak dient ein kleiner Server auf Port 18099, der die Header der Anfrage
zurückgibt (python3 -I, nur für diese Messung, nicht im Repository).

P10:
$ curl -s -H 'X-Forwarded-Host: evil.example' -H 'X-Forwarded-Proto: https' -H 'X-Forwarded-Port: 65000' \
    -H 'X-Forwarded-For: 203.0.113.7' -H 'X-Forwarded-Prefix: /evil' \
    -H 'Forwarded: for=203.0.113.7;host=evil.example;proto=https' http://localhost:18090/auth/realms/chat/x
Connection: Upgrade, HTTP2-Settings
Host: localhost:18099
HTTP2-Settings: AAEAAEAAAAIAAAAAAAMAAAAAAAQBAAAAAAUAAEAAAAYABgAA
Upgrade: h2c
accept: */*
user-agent: curl/8.7.1
=> Alle sechs Header fehlen ganz, der Proxy setzt auch keine eigenen. Host ist der des Ziels
   (im Stack also keycloak:8080). Grund: Spring Cloud Gateway 4.3.5 reicht X-Forwarded-* und
   Forwarded nur weiter, wenn "trusted proxies" eingestellt sind (Klassen TrustedProxies,
   RemoveXForwardedRequestHeadersFilter, RemoveForwardedRequestHeadersFilter im Jar
   spring-cloud-gateway-server-mvc-4.3.5). Ein eigener Filter ist nicht nötig.
   Nebenbefund: Der HTTP-Client des Proxys bietet ein Upgrade auf HTTP/2 an (h2c).
